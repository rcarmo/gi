# Attachment upload state against Piclaw 3.2.4

Installed Piclaw 3.2.4 sent a media identifier only after a successful upload and retained the draft after a rejected upload. Gi's native `@ux-original-026` journey passed separately. The tests use disposable endpoints and a local test server respectively.

`make test-piclaw-upload-state` runs `tests/ux/oracle/piclaw-upload-state-probe.mjs` with shipped browser assets and mocked `/media/upload` and `/agent/default/message` endpoints. Six Chromium/WebKit phone, tablet and desktop cases passed. A successful upload returned `id:71`; the following message contained `media_ids:[71]` and `attachment:71 (accepted.txt)`. The next upload returned `503` with `fixture upload refused`; the composer showed the error, restored `retain rejected file` and its file pill, and made no second message request. Evidence: `test-results/ux-oracle/upload-state/evidence.json` and `/workspace/tmp/gi-upload-oracle-final.log`.

The first attempt failed because the test's global text locator matched both the composer notice and an agent-thinking error surface. Scoping it to `.compose-inline-status-detail` corrected the test without changing Piclaw. The failed attempt is in `/workspace/tmp/gi-upload-oracle-attempt1.log`.

`make test-ux-parity UX_PARITY_ARGS='tests/ux/drafts.spec.mjs --grep "@ux-original-026"'` passed 6/6 in Gi (`/workspace/tmp/gi-upload-native-original026.log`). That native journey forces multipart parsing failure, checks that no prompt is admitted, retains text/files, and retries with durable media IDs. The Piclaw fixture does not test production storage, provider delivery, mixed batches, or retry deduplication. `make check ux-parity-inventory` passed 144 functional tests with 11 skips and 214 support tests with 7,977 assertions (`/workspace/tmp/gi-upload-check-final.log`). The first run had 143 passes and failed before the bundle assertion when a functional case never left the app loading screen (`/workspace/tmp/gi-upload-check.log`); the unchanged complete rerun passed. `@ux-original-026` was already mapped; this comparison adds no mapping credit.
