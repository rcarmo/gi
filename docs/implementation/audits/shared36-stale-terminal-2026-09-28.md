# Shared36: stale terminal frame after a newer run starts

The installed Piclaw 3.2.4 Classic UI kept Stop on a newer turn when a synthetic terminal status frame for the previous turn arrived. `make test-piclaw-stale-terminal` passed six Chromium/WebKit phone, tablet and desktop fixtures. Each fixture sent two active same-chat statuses, replayed `done` for the older turn, then sent `done` for the newer turn. Stop remained visible after the old frame and disappeared after the new frame. `/agent/status` continued to return the newer turn until its terminal frame.

The fixture uses the shipped UI and pinned Piclaw assets, with local status/SSE responses. It does not disconnect SSE, cancel a real run, check queue persistence or exercise production HTTP authorisation. Its 100 ms settle and 250 ms observation intervals cannot establish every interleaving. The earlier Piclaw Stop UI probe separately checks `/abort` with `mode: steer` and retained draft; the installed abort/finalisation method probe covers queued work with disposable collaborators.

Gi's `tests/ux/reconnect.spec.mjs` has a native local journey covering a disconnected/reconnected busy turn, captured turn-ID cancellation, queue advancement, draft/attachment preservation, another session, and replay of old native terminal frames. That journey was formerly tagged to Shared36 when Gi had an extra hold-and-Resume contract. The invalid mapping was withdrawn. This new Piclaw fixture confirms only the stale-frame subclause. Keep Shared36 unmapped until the combined reconnect, ownership, Stop and queue journey is compared and accepted against the installed oracle; do not restore the hold-and-Resume contract.
