# Classic BTW panel, 28 September 2026

The installed Piclaw 3.2.4 Classic client handles `/btw <question>` in a mounted side panel. `make test-piclaw-btw-panel` passed six Chromium/WebKit phone, tablet and desktop cases against shipped UI assets and disposable HTTP responses. An intercepted `/agent/side-prompt/stream` request received an error, then Retry issued a second request with the same question and chat JID. While running, the answer and action footer were absent. The error state showed its error and disabled Inject; a successful streamed response showed thinking and answer text and enabled Inject. Activating Inject issued one intercepted main-chat message containing the question and answer. The fixture did not run a provider, persist the injected message, or test a real queue.

The mounted Gi composer did not intercept `/btw <question>`. `make test-ux-btw-mount` passed six Chromium/WebKit browser cases against a disposable native HTTP server: the command reached `/api/sessions/{id}/prompt`, the fixture rejected that ordinary prompt admission, the draft stayed in the composer, and no `.btw-panel` or turn appeared. Gi's `web/src/components/btw-panel.ts`, `web/src/ui/app-sidepanel-orchestration.ts` and `web/src/ui/app-main-shell-render.ts` contain panel and callback code, but `web/src/app.ts` does not mount that shell. `web/src/api.ts` also returns `null` from its `streamSidePrompt` stub. Those copied pieces do not provide the mounted side-question flow.

`@ux-extra-001` remains unmapped. The installed probe checks a subset of the frozen panel contract through a synthetic error, stream and intercepted Inject request. It does not establish a live provider or persisted injected turn. The Gi probe establishes a mounted entry gap; it does not validate an alternative BTW workflow. No production code, frozen Gherkin or live chat was changed.
