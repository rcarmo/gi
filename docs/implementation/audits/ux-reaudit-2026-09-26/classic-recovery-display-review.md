# Classic recovery display, 28 September 2026

The installed Piclaw 3.2.4 Classic client and Gi do not display the same eight recovery fixture rows. `make test-piclaw-recovery-display` used the shipped UI with 23 control-intent and 21 placeholder posts from Gi's fixture files in each of six Chromium/WebKit phone, tablet and desktop cases. It observed the same eight differences in every case; the other 36 rows matched the fixture visibility expectations. This compares displayed posts only. It did not run recovery, persist a backend message, exercise search or test a physical device.

| Clause | Installed observation | Boundary |
| --- | --- | --- |
| `@ux-extra-012` | Three valid protected controls were hidden, as were `legacy-partial-failure` and `legacy-bad-failure`, which Gi keeps visible. | Installed `components/post.ts` accepts a block without typed handoff keys before validating partial primary-failure fields. Gi's `gi-recovery-control.ts` validates those fields even on legacy-shaped blocks. The frozen rule says invalid typed recovery fields do not qualify. A partial or malformed `primary_failure_*` value is typed recovery metadata even without typed handoff keys, so Gi's visible result follows that rule. Installed Piclaw's hidden result conflicts with this frozen edge. Keep the mapped Gi fixture journey qualified; it earns no installed parity credit. |
| `@ux-extra-013` | The empty informational placeholder was hidden. The installed UI also hid the fixture's `file`, `file-ref`, `message-ref`, `attachment-ref`, `resource` and `text-annotation` posts, which Gi displays. | A follow-up `make test-piclaw-recovery-classic-shapes` passed 6/6 viewports with eight focused disposable posts: the empty info row stayed hidden, an authored row showed, and a file row with Classic `media_ids` plus a file block showed. File, message and attachment reference lists were still hidden after Classic extracted their text; resource and annotation-only blocks were also hidden. Installed `post.ts` checks `shouldRenderContent`, `media_ids`, direct cards and submissions, but not those other extracted extras. The prior six differences combine one missing media projection with five actual display-predicate boundaries in this synthetic shape; equivalence to live backend posts is untested. |

`make test-ux-recovery-controls` and `make test-ux-recovery-placeholders` retain separate native Gi HTTP/SQLite, reload, search and draft checks. A live/backend media and reference journey is needed before accepting the five remaining visible-extra boundaries. Do not relax Gi's control validator solely to copy Piclaw's mixed legacy edge: that would hide posts with invalid typed recovery metadata contrary to the frozen clause. The existing catalogue mapping denotes the Gi fixture journey, not installed parity acceptance. No production code, frozen Gherkin or live chat was changed.
