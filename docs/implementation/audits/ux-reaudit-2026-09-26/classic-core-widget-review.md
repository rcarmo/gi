# Classic generated-widget SSE and dismissal, 28 September 2026

The installed Piclaw 3.2.4 Classic UI did not display a live floating pane after receiving synthetic same-chat widget events. `make test-piclaw-widget-events` used the shipped assets with a disposable HTTP fixture in six Chromium/WebKit phone, tablet and desktop cases. Each case showed the `Oracle status ready` control from an `agent_status` frame; an independent listener on the same browser EventSource saw `generated_widget_open`, `generated_widget_delta` and `generated_widget_final` in order. Each case ended with zero `.floating-widget-pane` elements, an intact unsent draft and no queue-mutation POST. The fixture's authoritative status GET stayed idle, so its visible status title came from SSE.

The shipped `app.bundle.js.map` embeds `src/api.ts` with `bindJsonEvent('agent_status')` and no `generated_widget_*` binding. It also embeds a `resolveLiveGeneratedWidgetEvent` helper, but source presence does not make the helper reachable. The missing client registration explains the observed negative journey at this boundary; the probe did not exercise a live backend, persisted artifact, provider, real queue or physical device.

## Frozen clauses and Gi mount

- `@ux-extra-004` requires usable non-empty persisted artifact content and permits unfinished live loading/streaming/final/error states. `make test-piclaw-widget-persisted` passed 6/6 installed Chromium/WebKit viewports with disposable timeline posts: empty HTML/SVG disabled launch, populated HTML/SVG enabled launch and opened iframe content. The fixture's top-window bootstrap must not run in widget frames; the opaque SVG iframe produced one expected sandbox service-worker getter error in each case. Gi's `make test-ux-widget-persisted` passed 6/6 native HTTP/SQLite-backed browser cases with four seeded assistant messages: empty HTML/SVG launches disabled, populated launches opened iframe content, and closing left the draft and stored messages untouched without creating turns. This is a test fixture, not a provider or live-widget run. `web/src/ui/generated-widget.ts` and `app-generated-widget-events.ts` implement relevant helpers; mounted `web/src/gi-sse-client.ts` omits `generated_widget_*` listeners, and `web/src/app.ts` has no live-widget event branch. The frozen clause has no whole-clause acceptance credit.
- `@ux-extra-005` requires a **visible live widget** to record dismissal of that session while leaving follow-ups alone. Gi's mounted `web/src/app.ts` passes `onClose=${() => setFloatingWidget(null)}` and a no-op `onWidgetEvent`. Its close callback does not call a queue mutation, but it does not record the live session key. The separate `app-floating-widget.ts` dismissal helper is unused there. A pane that never opened cannot test dismissal or follow-up ownership. This clause has no acceptance credit.

Keep both frozen clauses unchanged and unmapped. Do not port helper code to satisfy the probe's negative observation. A future acceptance journey needs a visible live pane, the persisted-versus-live states, closing and replay of the same session key, plus independent queue evidence. The installed 3.2.4 shipped UI cannot currently supply that live SSE journey through its registered events. The installed persisted browser probe used disposable timeline posts; it did not test backend persistence. Gi's browser fixture used its real HTTP/SQLite path for seeded messages, without provider execution. No production code or live chat was changed.
