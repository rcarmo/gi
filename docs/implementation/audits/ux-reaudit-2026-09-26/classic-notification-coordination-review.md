# Classic local notification coordination, 29 September 2026

The installed Piclaw 3.2.4 Classic UI published one selected-chat browser presence record and withdrew it on `pagehide` in each of six Chromium/WebKit phone, tablet and desktop fixture cases. `make test-piclaw-notification-presence` observed one synthetic `/agent/push/presence` POST per case, a `piclaw.notifications.presence.*` local-storage record scoped to `web:default`, and removal of that record after a `pagehide` event. This covers the mount and withdrawal path without asking for notification permission or delivering a system notification.

A second installed mounted-path probe, `make test-piclaw-notification-leader`, passed six Chromium/WebKit viewports. It sent three synthetic final replies through the shipped SSE client with a mocked browser `Notification` and browser-local same-device presence: a visible `client-a` suppressed delivery, a hidden `client-a` led over hidden `client-b`, and removing `client-a` let `client-b` create exactly one local notification for the third reply. Raw SSE listeners confirmed each reply and terminal status reached the browser; the fixture did not use server presence fanout. The shipped `app.bundle.js.map` contains the mounted `useNotifications` hook and `notification-delivery-coordinator.ts`, which select the same rule. Gi's `web/src/gi-notifications-state.ts` calls that coordinator through its own lock and seen-list. `make test-notification-helpers` checks candidate and cross-client decisions; `make test-ux-notifications` uses mocked permission and delivery across six browser projects, including visible-tab suppression, hidden ownership and logout. The Gi tests are not tagged to `@ux-extra-011`.

The installed browser probes exercise one actual mounted client and one synthetic sibling record. They do not demonstrate two mounted clients receiving the same event or OS delivery. Server presence fanout, OS permissions/sound, cross-device coordination and physical devices have not been tested. Leave `@ux-extra-011` without whole-clause parity acceptance; do not port the helper again solely because the source matches.
