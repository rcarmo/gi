# WebKit reload failures in disposable Gi UX tests

A fresh bounded repeat reproduced an intermittent WebKit navigation failure, but did not reproduce the earlier `Loading Gi…` stall. The exact `@ux-compose-001` test ran five times in the WebKit-phone project against a disposable Gi instance: **four passed, one failed**. The failure occurred at `tests/ux/drafts.spec.mjs:92` inside `page.reload()`, before the test clicked the post timestamp or exercised the captured-draft path. The test assertions, 30-second timeout and production code were unchanged.

Command: `make test-ux-parity UX_PARITY_PORT=19178 UX_PARITY_ARGS='tests/ux/drafts.spec.mjs --grep "@ux-compose-001" --project=webkit-phone --repeat-each=5'`. The log is `/workspace/tmp/gi-ux-loading-webkit-repeat.log`. The failure screenshot, context and trace were preserved under `/workspace/tmp/gi-ux-loading-webkit-artifacts/drafts--ux-compose-001-Cle-0afed--while-allowing-a-new-draft-webkit-phone-repeat2/` before any further run could overwrite them.

The Playwright trace reports `page.reload: WebKit encountered an internal error` while waiting for navigation until `load`. Its network record marks the new **document** `GET /` with status `-1` and `_failureText: WebKit encountered an internal error`. Immediately after that, several in-flight session API fetches on the old page reported access-control errors during the aborted navigation. Earlier API reads in the trace returned 200, and the error-context snapshot still showed the conversation and composer with a `Load failed` alert. These records establish an aborted WebKit navigation in this run; they do not identify a Gi server response failure, product code defect or root cause inside WebKit.

The earlier first compose gate passed 29/30, then timed out on WebKit phone after reload with only `Loading Gi…` and no `.post-time`. An unchanged rerun passed 30/30. Its named trace files were later overwritten, so the new navigation trace cannot establish the cause of that older loading-only symptom. Keep both failures visible and separate. Do not weaken the `.post-time` assertion, skip WebKit or increase the 30-second timeout on this evidence. If the loading-only stall recurs, preserve its trace, HTML asset and document responses, console/page errors and server log before rerunning; compare them with the aborted-navigation trace.
