# ADR-0020: Render automatic compaction from native activity

## Status

Accepted — 2026-09-22. Automatic lifecycle only; manual compaction is unavailable.

## Native activity and cancellation

`GET /api/sessions/{id}/activity` reads the session claim, turn phase and latest compaction occurrence in one SQLite statement. A running row without a claim is idle. When no claim exists, only the most recent non-queued turn can supply a brief suppression/failure notice; older turns cannot resurrect a notice after new work. The snapshot contains the persisted start timestamp and event sequence.

`POST` to the same endpoint accepts `{ "turn_id": "..." }` and cancels only that active session/run. Malformed requests return 400, missing sessions 404 and stale/foreign/inactive runs 409. `Engine.CancelActiveTurn` repeats claim/current-run checks under the runner lock and has no queued-cancellation fallback. General cancellation and queued cancellation retain their separate contracts.

## Browser ownership

Native compaction events and turn lifecycle invalidations trigger a fresh activity/model/queue read. The app rejects replies from earlier selection, connection or activity revisions. An event does not directly paint compaction state. Reload uses the persisted occurrence timestamp, so elapsed time does not restart at zero. Switching sessions or disconnecting clears transient activity.

The host supplies `statusNotice` to the existing composer, which already supports the compacting spinner and inline notice. A scoped app adapter adds `is-compacting`, elapsed text and compaction title/ARIA/tooltip values to the existing context meter. It restores ordinary context presentation after terminal activity. The optional manual compaction callback is still absent and the meter remains disabled. No supplied component, UI utility or pane is edited.

The adapter intercepts the visible Stop click before the component's `/abort` command path can clear drafts or upload attachments. Stop requires a fresh native run snapshot and is disabled while the snapshot is invalid or cancellation is pending. The captured run ID never changes during the request. A 409 completion race reconciles state without cancelling later work; transport errors remain visible until retry or session switch. Stop feedback belongs to its origin generation. A delegate review identified the stale/no-op control gap; tests subsequently exposed refresh clearing the error too quickly. Both were fixed before the final matrix.

Suppression/failure notices use the persisted native detail and expire after ten seconds. Normal completion refreshes measured usage; no estimate replaces it and no shrinkage is promised. The fixture deliberately reports 180 prompt tokens after an earlier 100-token request.

## Evidence

- Six mappings: `compaction-001` through `005`, plus `context-004`.
- 48/48 Chromium/WebKit phone/tablet/desktop executions: native history generated by real turns, actual before-compact hook gates, elapsed/style/title state, completion, cancellation, suppression detail, larger post-compaction usage, retained text/media, reload, delayed poll/session switch, failed Stop and late completion conflict.
- Existing 228/228 browser executions and 70/70 functional tests pass. Combined browser executions: 276/276. Classic 25/236 pass, 211 unmapped; shared 2/42 pass, 40 unmapped.
- Full Go tests/vet, hook checks, 24 helpers and targeted native race tests repeated three times pass. The activity API tests cover unknown/foreign/stale runs, occurrence snapshots, lost claims and new-turn notice isolation.

Use `make test-ux-compaction`. The isolated local-provider fixture exercises production inference, hooks, persistence and SSE; no paid provider, SQL-seeded history, synthetic lifecycle messages, forced controls or test retries. Combine its explicit result file with the other four matrix files.

## Remaining work and terminal adaptation

Manual Compact and `context-003` are not implemented. This slice does not add a persisted history boundary; subsequent turns still include original history alongside stored summaries. Broad socket-reconnect/full crash acceptance and summary quality need further work. Automatic compaction lifecycle evidence does not complete those contracts.

Terminal adaptation uses existing transient status and cancellation keys, with `Compacting context m:ss` in the existing footer/status region, and a brief suppression/error notice. It must not add an idle row, top bar or permanent panel. Captured session/run/occurrence ownership must apply to elapsed updates and cancellation feedback. Verify 60×18, 100×22 and 140×36, draft/cursor preservation, resize, stale completion and stop failure before claiming live terminal parity. The current TUI retains its existing completion rendering; this web slice adds no terminal UI or live-terminal credit.
