# go-ai 1.3.0 alignment

Target release: `github.com/rcarmo/go-ai v1.3.0`, tag commit `d9449bf4b102eb4303b8c60e9b0649b4bf99d08f`, upstream pi revision `71023aec1546d6d677a65669c5665c0927ce0dd0`. This branch builds on the verified, unmerged 1.2.0 candidate from Gi PR #55; frontend PR #2 also remains unmerged.

## First contract slice

1.3 adds `ArgumentsError` to tool calls/content blocks and preserves provider parse failures through `GetToolCalls`. Gi now rejects marked calls before tool-call/approval/result hooks and executor effects. Rejection commits an error result and fresh terminal occurrence atomically, without an execution start or invented duration. Assistant call summaries and fallback replay retain the marker.

Development verification: Go1.27.1, project-owned isolated test environment with inherited agent-directory overrides unset. Focused malformed-call/replay tests pass race ×3; inference, turn and store suites pass. No 1.3 pre-release profiling, full suite or browser matrix has run yet.

## Remaining audit

- Malformed-only batches now skip execution start/end hooks; mixed batches count executable calls only. Direct/nested guards run before lookup/hooks/effects. Nested null/array/scalar/truncated inputs reject; marked call/error-result pairing survives database reopen. Focused tests race ×3 and full turn/inference/import/export suites pass. Hook-mutated invalid calls now reject immediately after tool_call/approve_tool replacement, before later hooks or execution; nested same-name replacements preserve this boundary. Mixed batches retain ordered error/error/success results and only start the valid call. Focused mixed/hook/nested regressions pass race ×3; turn/inference/import/export suites pass. Batch start/end count means initially executable candidates (excluding parser-marked inputs), not successful executions; a candidate later rejected by a hook stays in that initial count.
- Direct dispatch rejects the marker before lookup; import/export preserves argumentsError. Focused direct/import/export/malformed-call/reopen and batch-hook tests pass race ×3.
- Removed AssistantMessageFrame/encoder/reducer API: no Gi source references found; regular SSE/provider MessageEvent paths remain in use.
- Compatibility SSE now accumulates argument fragments by index and validates completed object JSON, preserving ArgumentsError into the emitted content block. HTTP fixture tests cover split/interleaved valid objects, array/null/truncated failures and empty arguments; race ×3 plus full inference/turn suites pass. Completed-call repair now follows the tagged go-ai v1.3.0 internal helper for invalid escapes/control characters (MIT attribution in source); tests verify repaired values and reject truncated/non-object/trailing data. Focused tests race ×3 and full inference/turn suites pass; no paid-provider acceptance or exhaustive provider-specific compatibility flag claim.
