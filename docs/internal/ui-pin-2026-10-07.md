## Backend compatibility

The served bootstrap and hashed module graph resolve against the committed
assets. Targeted checks cover session creation/forking, prompt targeting,
media uploads and retry ownership, queue steering, side-prompt SSE, workspace
editor routes/confinement, and precompressed assets.

The five extracted viewer pages need their own response policies. Gi now
serves their directory and `index.html` routes, including `/static` aliases,
with the pinned CSP, `X-Frame-Options: SAMEORIGIN` and `Cache-Control: no-cache`.
Tests compare the policy strings with the pinned extraction manifest and
check GET/HEAD, missing assets and policy isolation. The app's bootstrap
continues to use its existing no-store policy.

Optional `/agent/ui-state` and `/post/{id}/annotations` APIs are not implemented
in Gi; the UI contract allows 404 degradation. `/agent/respond` and
`open_workspace_file` acceptance remain separate work. This pin does not close
editor, terminal, VNC or side-prompt UI acceptance issues, change capability
claims/skips, or reconstruct the frozen v0.2.0 compliance run.

## Profiling and preservation

Backend CPU, `alloc_space` and `alloc_objects` were inspected. Cumulative CPU
was dominated by SQLite setup and asset-graph test traversal. Precompressed
asset copying and inference catalogue setup dominated allocated bytes; test
matching and SQLite calls dominated object counts. The viewer middleware
uses a fixed five-entry policy map and does not parse JSON per request.
No measured performance improvement is claimed.

Bun captures contained 30 ms of sampled Classic JavaScript and 60 ms of
contract JavaScript. Source-pin verification/read work dominated the former;
schema compilation accounted for 34 ms in the latter, with the upstream
compiled-validator cache already in place. Exit heaps held about 1.85 MiB
and 4.20 MiB respectively. These are live snapshots, not allocation histories;
subprocesses and browsers were not profiled. Raw profiles, disposable logs,
matching binaries and owned run scratch were removed after analysis.

The submodule's only local edit was the Rui profiling-policy header. Every
added line already exists in the target revision; the original edit is also
preserved in its named Git stash (`8d37570fcd3fa599eb9eec2f4a18ff6e496489e3`).
The unrelated `third_party/joker/AGENTS.md` edit remains untouched.
