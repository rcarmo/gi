# go-ai 1.2.0 alignment

Gi's upgrade branch pins `github.com/rcarmo/go-ai v1.2.0`, release commit `a927454af26e172462b0ed0d0acc3be9978dde38`. That release targets upstream pi `v1.2.0`, revision `06a466935536f8c9bcacb2d5efc0fc021be1bdff`. The local go-ai development checkout has started 1.3 work; it is not the upgrade baseline.

## Runtime boundaries and gaps

Gi uses go-ai's provider APIs, model catalogue and OAuth support. Gi owns its turn loop, tool hooks, compaction, SQLite store and web projections. Updating the module does not automatically adopt go-ai/durable's runtime contracts.

## Development verification

Go 1.27.1, project-owned test environment, inherited `PI_CODING_AGENT_DIR` and `GI_CODING_AGENT_DIR` unset:

- `go test ./internal/inference ./internal/store ./internal/turn -count=1` passes after the upgrade and transactional append changes.
- Atomic append failure and normal store flow regressions pass with `-race -count=3`.
- Full store suite passes `-race -count=3` after the terminal conversation projection.
- Candidate consumer matrix: five checks × six projects = 30 passes, zero retries. Covers live nested settlement/reload, failure, two sessions, cancellation/reload and absent-details compatibility injection. The absent-details check modifies real saved HTTP rows and is not live execution evidence.
- Projection regressions cover equal timestamps, backward/forward paging, reused tool-call IDs with distinct occurrences, first-terminal-wins, session fencing, raw-history exclusion and persisted-result deduplication.
- Atomic settlement tests inject failures at event insert, message insert, turn update and session update. Both rows roll back; cancelled admission fails; a subsequent successful pair survives reopen. Focused race tests pass ×3 and full store/turn tests pass.
- Targeted profile: Go 1.27.1, candidate based on 3a2b4847, 30 repetitions of settlement/reopen, append rollback and conversation paging tests. CPU sampled 1.52 seconds over 3.93 seconds; database/sql locking was 57.24% cumulative and store.Open 38.16%. Allocation history: 124.30 MB / 764,902 objects; regexp compilation was 63.23% cumulative alloc_space and 50.89% alloc_objects. This workload repeatedly opens databases and validates schemas; it does not isolate steady-state tool settlement. No equivalent-workload speedup measured; regex attribution needs deeper caller analysis before tuning. Captures and matching binary were deleted immediately after analysis.
- Hook response engine regression passes race ×3 and verifies shared event/message occurrence plus absent execution duration. Admission boundary tests pass race ×3. Full store/turn suites pass.
- The candidate six-project web matrix was rebuilt and rerun after normal and hook settlement changes: 30/30 passes, zero retries.
- Fork audit: CloneSessionBefore copies messages transactionally with fresh IDs and source provenance, resets live routing/work state, and does not copy terminal events or context checkpoints. Existing tests cover concurrent clones, invalid cutoffs and rollback. New fork/reopen replay and unsplittable compaction-boundary regressions pass race ×3; full store/turn suites pass. ContextSnapshot previously omitted saved tool results and flattened calls into assistant text; typed replay now restores call arguments and result identity/error/details. Replay now retains tool images and successful added-tool names plus full provider assistant messages/signatures. Focused tests pass race ×3, including provider orphan repair at a user boundary with a reused call ID; no duplicate repair implementation was added. Assistant tool-call persistence failures now stop execution before tools run. Inference/store/turn suites pass. Large image retention, provider-message privacy/API projection and upstream reset equivalence still need verification.
- Internal replay images use `provider_content_blocks`, separate from UI `content_blocks`. Conversation pages/search strip `provider_message`, `provider_content_blocks` and internal added-tool names; display blocks survive. HTTP privacy regressions pass race ×3 and prove raw export/model snapshots retain replay data. This protects the newly added replay envelope; existing explicit thinking-panel metadata policy is unchanged.
- Rebuilt six-project browser matrix after typed replay, image/signature preservation and privacy projections: 30/30 passes, zero retries. Store/turn suites pass.
- Large-image integration: deterministic valid 512×512 PNG above 100 KB survives a failed result, reopen and fork; dimensions and sampled lossless pixels remain exact. Provider bytes stay absent from conversation pages. Test passes race ×3; full turn/store/web suites pass.
- In-flight cancellation integration: SQLite BEFORE INSERT trigger blocks at a registered scalar-function barrier; parent context is cancelled while blocked, then released. Admitted event and message both commit. Test passes race ×3.
- Targeted image profile (5 repetitions): 430 ms CPU sampled over 512 ms; PNG fixture encoding is 37.21% cumulative. Allocation history 215.42 MB / 72,212 objects; bytes.Clone 40.18 MB flat, JSON makeString 31.57 MB, store payload decoding 21.53 MB flat. Object counts are dominated by image/SQLite/catalogue setup. The fixture includes image encoding, reopen and fork, so these are not steady-state throughput measurements. Added a typed replay decode fast path to avoid JSON round-trips for already typed values; no measured speedup claim. Raw profiles and matching binary disposed after analysis.
- Reset audit: TUI /new and web session creation allocate a fresh session identity; active-tool reset is a separate per-session codemode/loadout operation. No destructive in-place message reset was found. This differs in surface from upstream durable reset; full equivalence is not established.
- Full pre-release profiling across runtime/frontend workloads and committed-pin web acceptance have not run.

Protected dirty F3 and Joker edits in the original checkout were not changed by this slice.
